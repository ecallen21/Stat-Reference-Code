# SPIN — Self-Play Fine-Tuning (Reference §47.200)

Chen, Deng, Yuan, Ji & Gu (2024, ICML). Alternates:

    Round t: opponent = model_{t-1}. Player = model_t.
    Objective: model_t should distinguish HUMAN samples from
                 samples generated by model_{t-1}.

Loss = −log σ(logπ_π_t(y_human) − logπ_π_t(y_from_opp))
No preference labels needed; the model improves by fooling its
own prior version. Similar to GAN training but on an
autoregressive LM.

## Files

- `python/spin_self_play_fine_tuning.py` — toy SPIN on a 6-way
  categorical distribution matching a target 'human' distribution
  [0.05, 0.40, 0.05, 0.35, 0.10, 0.05]. Five self-play rounds:
  - Round 1: KL(π ‖ human) = 0.30
  - Round 3: KL = 0.10
  - **Round 5: KL = 0.075** — converges toward the target using
    only human samples, no preferences.
- `r/spin_self_play_fine_tuning.R` — no R port; recommends
  `uclaml/SPIN`, `trl.SFTTrainer` + custom self-play loop.

## When to use

- **Cold-start alignment** with only SFT-quality data (no
  preferences).
- **Bootstrapping a weak model** with a small human corpus.
- **When preference data collection is expensive** (medical /
  legal domains).

## When NOT to use

- **When preference data exists** — DPO / KTO / SimPO are more
  direct.
- **Very small base models** — the discriminator gets stuck.
- **When the reward landscape is highly multimodal** — self-play
  can lock into a local mode.

## Assumptions & caveats

- **Opponent quality** matters — the previous round's model must
  be good enough to provide informative negatives.
- **Round budget** — 3-5 rounds typical; more risks over-fitting
  to the discriminator artifact.
- **Reference model** frozen at initial SFT; some variants
  refresh periodically.
- **Reward hacking** — model may learn to exploit
  distinguishable-from-human artifacts.
